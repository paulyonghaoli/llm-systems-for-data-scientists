# The retrieval corpus

Modules 3 and 4 and Capstone I all bind to this corpus. It is generated by
[`tools/build_corpus.py`](../../tools/build_corpus.py) from seed `20260811`,
measured by [`tools/verify_corpus.py`](../../tools/verify_corpus.py) (gate 25),
and that measurement is itself tested by
[`tools/test_verify_corpus.py`](../../tools/verify_corpus.py) (gate 26).

Rebuild with:

```bash
python tools/build_corpus.py && python tools/verify_corpus.py
```

## What this is, and what it is not

**The prose is template-generated, not hand-written.** 2,419 documents at ~370
tokens each is roughly 0.89 M tokens; nobody authored that by hand and this
document is not going to imply otherwise. What was authored is the *generator
and its templates* — the seven document types, the register differences between
them, the filler pools, and the phenomena planted into them. The sentences
themselves are recombinations.

That has a consequence worth stating up front, because it bounds what any
result measured on this corpus is worth: **the corpus is synthetic, so it
rewards retrievers that handle the specific difficulties planted in it and says
nothing about difficulties nobody thought to plant.** A retriever that scores
well here has not been shown to score well on real documents. It has been shown
to handle vocabulary mismatch, lexical distractors, superseded versions,
near-duplicates, multi-hop questions, contradictions, and unanswerable
questions — because those are measured, below — and that is the entire claim.

The alternative was a real public corpus. That was rejected in PLAN §10a: real
corpora carry licence terms that a shared static site cannot honour, they need
downloading (so the site stops being self-contained), and their gold labels are
not aligned to the specific phenomena these lessons teach. A synthetic corpus
with *measured* properties is worth more here than a real corpus with
*assumed* ones.

## Shape

| | |
|---|---|
| documents | 2,419 |
| queries | 200 |
| text | 3.58 M chars, ~0.89 M tokens |
| mean document | 370 tokens (median 373, sd 142) |
| documents over 512 tokens | 365 |

Document lengths vary *within* a type and differ *across* types — both
properties matter, and two earlier versions of the generator had one without
the other:

| type | n | mean tokens | p10 | p90 |
|---|---:|---:|---:|---:|
| policy | 19 | 785 | 449 | 1088 |
| handbook | 48 | 726 | 442 | 985 |
| agreement | 120 | 518 | 284 | 711 |
| incident | 900 | 385 | 223 | 530 |
| faq | 12 | 348 | 209 | 553 |
| shipment | 1,200 | 338 | 157 | 514 |
| release | 120 | 219 | 126 | 311 |

A first version gave every document of a type almost exactly the same length
(handbooks spanned 397–398 tokens), which is template regularity showing
through and leaves chunk-size choices nothing to bite on. Fixing that with one
wide range for all types then made policies and shipment records the same
average length, which no real operational corpus looks like. The range is now
per type.

**Documents, not chunks.** An earlier draft shipped pre-chunked text, which
left Module 3's chunking lesson with nothing to chunk. Gold labels are at
document granularity, as is standard in IR.

## The seven phenomena

Each is *measured*, not asserted. The distinction is the point: the generator
intends to plant a vocabulary mismatch when it writes a customer-register query
against an operational-register policy, but intent is not evidence — a template
that quietly shares one rare word between query and answer produces a query
BM25 finds easily, whatever the label says.

Thresholds come from what each phenomenon *means*, not from what this corpus
happens to produce. When a check fails, the corpus gets fixed, not the
threshold.

| phenomenon | n | measured property | threshold |
|---|---:|---|---|
| `vocabulary_mismatch` | 30 | 100% have gold outside BM25 top-5; mean query-term coverage 0.46 | ≥50%; ≤0.55 |
| `lexical_distractor` | 31 | 74% have a non-gold BM25 top-1 | ≥50% |
| `near_duplicate` | 30 | 100% have a sibling at Jaccard ≥ 0.70 (mean best 0.97) | 100% |
| `superseded` | 30 | 100% have a similar, non-gold predecessor | 100% |
| `multi_hop` | 31 | 100% need both documents for term coverage | ≥90% |
| `contradiction` | 24 | 100% have a rival document stating different numbers | ≥90% |
| `unanswerable` | 24 | mean top-1 score 11.1 vs 26.7 for answerable | strictly lower |

Gate 25 uses a plain BM25 with untuned Robertson defaults (k₁ = 1.5, b = 0.75),
written out in `verify_corpus.py` rather than imported, so these numbers depend
on nothing outside this repository — and a tuned retriever would make "BM25
fails here" a statement about the tuning rather than about the corpus.

## Why gate 26 exists

Gate 25 passed all nine of its checks the first time it ran. That is when a
check is *least* trustworthy, not most: a check that has only ever passed has
not been tested, and one that cannot fail is decoration. The silent-success
bugs available here all look identical to a green tick — an empty candidate
list, a `continue` that skips every item, a percentage over a zero denominator.

So gate 26 destroys each phenomenon in turn and requires gate 25 to notice. It
caught a real gap on its first run: a gold id naming a document that does not
exist raised `KeyError` halfway through the checks instead of being reported.
`verify_corpus.py` now validates referential integrity before anything else.

## Files

- `documents.jsonl` — one document per line: `doc_id`, `type`, `text`,
  `facts`, `superseded`, `doc_index`.
- `queries.jsonl` — one query per line: `query_id`, `text`, `gold_doc_ids`
  (empty for unanswerable), `phenomenon`, `note` explaining what makes it hard.

## Open decision for Module 3

`documents.jsonl` is 4.2 MB. That is fine in git and fine for graders that run
locally, but it is a lot to pull into a browser tab for an in-page exercise.
The likely resolution is a committed subset for Pyodide exercises with the full
corpus reserved for the capstone, but the subset size should be chosen against
a measured page load rather than guessed, so it is deferred to the lesson that
first needs it rather than invented here.
